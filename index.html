Example — how to build a filter
{
  "status": "open",
  "priority": "high",
  "assignee": { "name": "Amy" }
}

To find records where status is open AND priority is high, OR the assignee is Amy:

Group 1 → status equals open AND priority equals high
OR
Group 2 → assignee.name equals Amy

Type into the Attribute box to search for a field — start typing any part of its name and matches will appear. Nested fields use dot notation, e.g. assignee.name. Within a group you can mix AND and OR freely using the toggle between conditions, and when you add another group you can choose whether it combines with everything before it using AND or OR. Either way, conditions and groups apply in order from top to bottom — no hidden parentheses — so list everything you want AND'd together before switching to OR.

What checks will be applied

Every flight you paste in is run through these 5 checks, in this order. As soon as a flight fails one, it's excluded and the remaining checks are skipped for it (a flight only ever gets one reason for being filtered out) — this matches exactly how the real system decides which flights to process further.

1. Airline check — Is the flight operated by one of the customer's own airlines (currently KL, AF, DL, AM, CI, MU, CZ, A9, KQ, MF, HV)? If not, it's dropped straight away.
2. KL high-number check — Is it a KL flight with a flight number of 9000 or higher? These are treated as non-passenger / placeholder flights and are always excluded.
3. Amsterdam check — Does the flight depart from AMS or arrive at AMS? If it touches neither, it isn't relevant to us and is dropped.
4. Cancelled + excluded-airport check — If the flight is cancelled (and the cancellation happened within 14 days of the scheduled time), is its departure or arrival airport on the excluded-airports list (currently MSP, SLC, DTW, JFK, DBV, SPU, ZAG)? If so, it's dropped. This check is skipped for flights that aren't cancelled.
5. "Today" check — Is the flight actually scheduled for today, from Amsterdam's point of view? This covers flights departing AMS today, flights arriving at AMS today, and overnight flights that left yesterday but land in AMS today. If none of that matches, the flight is dropped as not relevant to today.

A flight only carries on to further processing if it clears all five checks. Before any of this runs, exact duplicate flights (same airline, flight number, departure date, departure airport and suffix) are quietly removed so they're only counted once. All dates and times in your JSON are treated as UTC and are converted into Amsterdam local time (CET in winter, CEST in summer) before any date comparison is made — so a flight timestamped late at night in UTC may correctly fall on the next calendar day once checked, and vice versa. Each result also shows a Flight status panel noting whether the flight is cancelled and whether it's delayed from AMS's point of view — delay is only reported for the AMS end of the flight (its departure if it departs AMS, its arrival if it arrives at AMS), not for the other end of the flight — including the exact attribute, its value in Amsterdam time, and how many hours/minutes late it is. This is extra information only and doesn't affect the pass/fail outcome above (except where cancellation is part of check 4).
